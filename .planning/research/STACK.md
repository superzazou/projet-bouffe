## Implementation Patterns

### Pattern 1 — Desktop week grid (`md:` and above)

Use CSS Grid with 7 equal columns. The grid is hidden on mobile via `hidden md:grid`.

```tsx
// Outer container: show only on md+
<div className="hidden md:grid md:grid-cols-7 border border-stone-200 rounded-xl overflow-hidden">
  {days.map((day, i) => (
    <div
      key={toDateStr(day)}
      className={`p-3 border-r border-stone-100 last:border-r-0 ${
        isToday(day) ? "bg-stone-50" : "bg-white"
      }`}
    >
      {/* day header + meal slots */}
    </div>
  ))}
</div>
```

Tailwind v4 note: `grid-cols-7` is generated by default. If a build error occurs, use the arbitrary value syntax `grid-cols-[repeat(7,minmax(0,1fr))]` — underscores replace commas in Tailwind v4 arbitrary values (breaking change from v3).

For very narrow desktops (tablet landscape < 900px with 7 columns), add `min-w-[100px]` to each column and `overflow-x-auto` on the container to allow horizontal scroll rather than crushing content.

### Pattern 2 — Mobile single-day view (`< md`)

Hide on desktop via `md:hidden`. Use a controlled slide approach — `selectedDayIndex` state drives a `translateX` on a `flex` wrapper containing all 7 day panels.

```tsx
// State
const [selectedDayIndex, setSelectedDayIndex] = useState(todayIndex); // 0–6

// Container: clips to one panel width, hides overflow
<div className="md:hidden overflow-hidden">
  <div
    className="flex transition-transform duration-200 ease-in-out"
    style={{ transform: `translateX(-${selectedDayIndex * 100}%)` }}
  >
    {days.map((day) => (
      <div key={toDateStr(day)} className="w-full shrink-0 p-4">
        {/* meal slots for this day */}
      </div>
    ))}
  </div>
</div>
```

Why state-driven translateX over CSS scroll-snap:
- Mini-bar and swipe stay in perfect sync — one source of truth (`selectedDayIndex`)
- No `IntersectionObserver` or `scroll` event debouncing needed to track which day is visible
- Navigation from mini-bar click is instant and deterministic
- Google Calendar mobile uses this exact pattern

### Pattern 3 — `useSwipeGesture` hook

Zero-dependency custom hook. Detects left/right swipe on touch devices. Threshold of 50px avoids accidental triggers during vertical scrolling.

```tsx
// hooks/useSwipeGesture.ts
import { useRef, useCallback } from "react";

export function useSwipeGesture(
  onSwipeLeft: () => void,
  onSwipeRight: () => void,
  threshold = 50
) {
  const touchStartX = useRef<number | null>(null);

  const onTouchStart = useCallback((e: React.TouchEvent) => {
    touchStartX.current = e.touches[0].clientX;
  }, []);

  const onTouchEnd = useCallback(
    (e: React.TouchEvent) => {
      if (touchStartX.current === null) return;
      const delta = touchStartX.current - e.changedTouches[0].clientX;
      if (Math.abs(delta) > threshold) {
        delta > 0 ? onSwipeLeft() : onSwipeRight();
      }
      touchStartX.current = null;
    },
    [onSwipeLeft, onSwipeRight, threshold]
  );

  return { onTouchStart, onTouchEnd };
}
```

Usage in the day-slide container:

```tsx
const { onTouchStart, onTouchEnd } = useSwipeGesture(
  () => setSelectedDayIndex((i) => Math.min(i + 1, 6)), // swipe left → next day
  () => setSelectedDayIndex((i) => Math.max(i - 1, 0))  // swipe right → prev day
);

<div
  className="md:hidden overflow-hidden"
  onTouchStart={onTouchStart}
  onTouchEnd={onTouchEnd}
>
  ...
</div>
```

Note: `e.changedTouches[0].clientX` is the correct API for `touchend` — `e.touches[0]` is empty at touchend because the finger has lifted.

### Pattern 4 — Mobile mini week bar

Sticky `flex` row of 7 equal-width buttons. Shows the full week at a glance and acts as a day picker. Today's date gets a filled circle; selected day gets a bottom border indicator.

```tsx
<div className="md:hidden sticky top-0 z-10 flex border-b border-stone-200 bg-white">
  {days.map((day, i) => {
    const isSelected = i === selectedDayIndex;
    const todayDay = toDateStr(day) === today;
    return (
      <button
        key={i}
        onClick={() => setSelectedDayIndex(i)}
        className={`flex-1 flex flex-col items-center py-2 text-xs transition-colors ${
          isSelected
            ? "text-stone-900 border-b-2 border-stone-900"
            : "text-stone-400 border-b-2 border-transparent"
        }`}
      >
        <span className="font-medium">{DAY_LABELS[i]}</span>
        <span
          className={`mt-0.5 w-6 h-6 flex items-center justify-center rounded-full ${
            todayDay ? "bg-stone-900 text-white font-semibold" : ""
          }`}
        >
          {day.getDate()}
        </span>
      </button>
    );
  })}
</div>
```

### Pattern 5 — Responsive week navigation (shared)

The existing week navigation (prev/next week buttons + week label) works for both views. On mobile, add a "Aujourd'hui" button that resets both `weekOffset` and `selectedDayIndex` simultaneously.

```tsx
// Reset to today
function goToToday() {
  setWeekOffset(0);
  setSelectedDayIndex(todayIndex); // index of today in the current week (0–6)
}
```

### Pattern 6 — `todayIndex` calculation

Add this derived value to the component (no library needed):

```tsx
const todayIndex = days.findIndex((d) => toDateStr(d) === today);
// Initialize selectedDayIndex to todayIndex (or 0 if today not in current week)
const [selectedDayIndex, setSelectedDayIndex] = useState(
  Math.max(0, todayIndex)
);

// When weekOffset changes, reset selectedDayIndex to today if today is in range, else to 0
useEffect(() => {
  const idx = days.findIndex((d) => toDateStr(d) === today);
  setSelectedDayIndex(idx >= 0 ? idx : 0);
}, [weekOffset]); // eslint-disable-line — days is derived from weekOffset
```

## Alternatives Considered

| Recommended | Alternative | When to Use Alternative |
|-------------|-------------|-------------------------|
| State-driven translateX for mobile | CSS scroll-snap | If you want zero JS for the swipe mechanism and accept that mini-bar sync requires IntersectionObserver wiring |
| Custom `useSwipeGesture` hook | `@use-gesture/react` | Only if the project already depends on it AND needs complex multi-gesture support (pinch, drag, etc.) — adds ~40KB for a 15-line use case |
| CSS Grid (`grid-cols-7`) | Flexbox with `flex-1` children | Flexbox `flex-1` works visually but is semantically weaker and cannot enforce min-width per column independently |
| Tailwind `md:` breakpoint (768px) | Custom breakpoint | Only if design specs require a different breakpoint — 768px aligns with iPad portrait which is the natural mobile/desktop split |

## What NOT to Use

| Avoid | Why | Use Instead |
|-------|-----|-------------|
| FullCalendar | 400KB+ bundle; designed for month/agenda views with drag-and-drop event scheduling; complex API that fights Tailwind reset styles; major overengineering for a 2-slot-per-day layout | CSS Grid + custom component (zero deps) |
| react-big-calendar | React 16-era design; requires either moment.js or date-fns as peer dep; CSS module approach conflicts with Tailwind utility workflow; no meaningful update activity | CSS Grid + custom component |
| framer-motion | 60KB for animation that `transition-transform duration-200` handles natively; adds complexity with AnimatePresence for conditional rendering | Tailwind `transition-transform duration-200 ease-in-out` |
| `@use-gesture/react` | 40KB library for detecting left/right swipe — a 15-line custom hook is sufficient and has no bundle cost | Custom `useSwipeGesture` hook (see Pattern 3) |
| CSS scroll-snap as primary mechanism | Requires IntersectionObserver or scroll event debouncing to keep selectedDay state in sync with mini-bar; partial-scroll state possible if user lifts finger mid-swipe; two sources of truth | State-driven translateX (Pattern 2) |
| `@dnd-kit` for swipe | Already in the project but designed for drag-and-drop reordering, not directional gesture navigation | Custom `useSwipeGesture` hook |
| date-fns / dayjs | The codebase already implements all needed date utilities (`getMondayOf`, `addDays`, `toDateStr`, `formatWeekLabel`) inline with ~20 lines of vanilla JS | Existing date utilities in `PlanningWeek.tsx` |

## Stack Patterns by Variant

**If the mini-bar needs to show meal indicators (colored dots per day):**
- Pass a summary of filled/empty slots as derived data alongside `days`
- Render small dots in the mini-bar button below the date number
- No new state or libraries needed — pure derived computation

**If the week view needs to handle tablet landscape (768–1024px) with cramped 7 columns:**
- Add `min-w-[90px]` to each column cell and `overflow-x-auto` on the grid container
- Alternatively use `sm:hidden md:grid` to show the grid only from 768px but allow horizontal scroll below 900px

**If the modal for recipe search on mobile (stated in PROJECT.md) reuses `RecipeCombobox`:**
- Wrap in the existing modal pattern (already used for shopping list creation in `PlanningWeek.tsx`)
- Pass `date` and `mealType` as modal context state; close modal on selection
